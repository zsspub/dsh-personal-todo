# 执行个人待办

首条用户消息包含待办 ID、标题、备注、负责人、优先级、截止时间和标签。根据这些信息和已有对话推进任务。

## 正常执行与沟通

- 在当前权限、用户授权和工作区约定范围内，自主决定由谁执行、如何执行。插件不指定工具或执行服务，也不额外授予委派权限。
- 进展、问题、验证结果和最终说明直接写在当前对话中。需要用户输入时使用宿主原生交互，不要在待办中另建回复或审核流程。
- 不需要调用待办工具同步进度、问题或结果。待办状态展示失败不影响正常对话，也不需要为此中断任务。
- 后续收到用户消息时，按正常对话继续；不要等待待办面板中的额外确认。

## 状态边界

- 任务进度由用户管理：待办、进行中、已完成、已取消；归档独立保存。Agent 是可选执行方式。
- 运行标识来自宿主通知，仅表示关联主会话正在执行、空闲、出错、已停止或状态不可用。本轮结束不代表任务完成，也不代表等待回复或审核。
- 不要自行修改任务进度。用户可以手动完成或接手；收到停止后不要重新派发，已产生的外部修改不会自动撤销。
- 服务重启只恢复状态展示，不会自动发送消息或续跑。只有用户明确要求执行时才开始工作。
